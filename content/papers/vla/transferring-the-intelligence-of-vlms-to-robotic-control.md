# 한 줄 요약

**RoboDawn은 사전학습된 VLM의 가중치를 그대로 유지하면서, 사람이 이해하기 쉬운 로봇 명령·관측·피드백 인터페이스와 문맥 내 시연을 연결해 양팔 조작을 수행하는 시스템이다.** 핵심은 새로운 action model을 학습하는 것이 아니라, 기존 모델이 가진 시각 이해와 추론 능력이 실제 행동으로 이어지도록 제어 문제의 표현을 바꾸는 데 있다.

이 글은 원문 전체를 번역한 문서가 아니라 방법과 실험을 설명하는 한국어 리뷰다. **원문에서 보고한 사실, 저자의 원인 추정, 리뷰어의 해석과 후속 제안을 구분한다.** 수치는 arXiv v1의 표를 기준으로 하며, 코드 공개 상태는 공식 저장소를 별도로 확인했다.

# 1. 문제의식: 이미 있는 지능을 로봇에서 사용할 수 있을까?

## 1.1 기존 접근이 주로 푸는 문제

VLA는 이미지와 언어 지시를 로봇 행동으로 연결한다. 일반적으로 사전학습된 시각·언어 모델을 가져온 뒤, 로봇 시연 데이터로 action prediction을 학습하거나 후학습한다. WAM은 미래 상태 예측과 행동 생성을 연결하는 방향을 탐구한다.

이 과정에서는 카메라 관측, 로봇 상태, 행동을 정렬한 데이터가 필요하다. 로봇의 관절 구조나 그리퍼, 센서가 달라지면 행동 표현도 달라질 수 있다. 성공 시연을 수집하고 다양한 물체·배치·조명에 대응하는 데이터를 늘리는 비용 역시 크다.

저자들은 별도의 우려도 제기한다. 좁은 로봇 행동 분포로 VLM을 미세조정하면 일반적인 지시 이해나 추론 능력을 훼손할 수 있다는 것이다. 다만 **이 논문 자체가 fine-tuning 전후의 일반 능력 저하를 직접 측정한 것은 아니다.** 기존 연구를 인용해 동결된 VLM을 사용하는 동기를 제시한다. [출처: 원문 §1–2](https://arxiv.org/pdf/2609.22966v1#page=1).

## 1.2 RoboDawn이 바꾸는 질문

이 논문은 ‘로봇 행동을 잘 예측하는 가중치를 어떻게 학습할까?’에 앞서 ‘이미 강한 VLM이 이해할 수 있는 형태로 로봇을 제시하면 어떻게 될까?’를 묻는다.

사람은 새로운 게임을 배울 때 매 순간 근육 제어를 다시 학습하지 않는다. 조작 규칙과 예시를 이해하고, 화면을 보면서 시도와 수정 과정을 반복한다. RoboDawn은 로봇 조작을 이와 비슷한 **관측 → 판단 → 의미 있는 명령 → 실행 결과 확인** 과정으로 만든다.

여기서 intelligence transfer는 서로 다른 몸체·환경·과업에서 기존의 지각, 추론, 계획 능력을 재사용한다는 연구 가설이다. 실험은 그 가설을 지지하는 사례를 제공하지만, 모든 로봇과 모든 동작에 대한 보편적 지능 전이를 증명하는 것은 아니다.

## 1.3 세 가지 구성 요소

1. **인터페이스:** 로봇 행동을 이동·회전·그리퍼 조작 등 의미 있는 명령으로 노출한다.
2. **문맥 내 시연:** 명령의 결과와 명령을 조합하는 과업 전략을 예시로 제공한다.
3. **폐루프 harness:** 관측, 상태, 피드백, 기억을 관리하면서 반복적으로 행동한다.

새로운 신경망 구조나 학습 손실이 핵심 기여인 논문은 아니다. 서로 맞물리는 입력·행동·피드백·시연 표현을 설계한 시스템 연구로 읽는 것이 정확하다.

# 2. 전체 구조: VLM과 로봇 제어기의 역할 분담

![RoboDawn의 인터페이스, 시연, 관측, 추론, 실행, 피드백 구조](/papers/assets/vla/robodawn/framework.png)

> 원문 Figure 2, PDF 5쪽에서 발췌. 상단은 명령과 시연, 가운데는 현재 관측과 추론·실행, 하단은 실행 피드백과 기억 갱신을 보여 준다. [그림 출처](https://arxiv.org/pdf/2609.22966v1#page=5).

VLM은 장면을 해석하고 다음 행동을 결정한다. 실제 관절 궤적 생성과 제어는 실행 계층이 담당한다. 따라서 VLM이 액추에이터에 고주파 제어 신호를 직접 보내는 구조로 이해하면 안 된다.

| 계층 | 책임 | 대표 입력·출력 |
| --- | --- | --- |
| 관측 계층 | 카메라와 로봇 상태를 모델 입력으로 구성 | 다중 시점 이미지, GIP 위치·자세, 그리퍼 상태 |
| VLM | 진행 상황 판단, 계획, 명령 생성 | 계획·scratchpad와 의미 명령 묶음 |
| 실행 계층 | 명령 해석, 목표 pose 변환, 동작 계획·실행 | 목표 GIP pose → 로봇 움직임 |
| 피드백·기억 계층 | 명령이 실제로 낸 효과를 다음 판단에 연결 | 도달 여부, 실제 변위, 실행 이력, 파지 정보 |

**행동의 의미를 정하는 문제와 행동을 물리적으로 실현하는 문제가 분리된다.** 이동 명령이 문법적으로 맞다는 것, 목표 위치가 타당하다는 것, 그 목표로 가는 경로가 충돌하지 않는다는 것은 서로 다른 조건이다. 뒤의 실패 분석은 이 차이가 실제로 중요함을 보여 준다.

# 3. Human-Intuitive Interface를 자세히 이해하기

## 3.1 GIP: 손목 대신 물체와 만나는 지점을 기준으로 한다

GIP(gripper interaction point)는 **그리퍼 양쪽 손끝 사이의 중점**이다. 로봇의 저수준 제어기는 손목이나 말단 링크 pose를 기준으로 동작할 수 있지만, 물체와 직접 상호작용하는 곳은 그리퍼 끝부분이다.

손목 좌표를 그대로 모델에 알려 주면 이미지에서 보이는 접촉 위치와 상태 숫자가 어긋날 수 있다. 그리퍼가 회전할 때 그 차이를 제대로 처리하지 않으면 위치 추정과 행동 결과 해석이 혼란스러워진다.

RoboDawn은 시각 주석, 로봇 상태 보고, 이동·회전 명령을 모두 GIP 기준으로 맞춘다. 같은 지점을 ‘보는 기준’, ‘숫자로 보고하는 기준’, ‘움직이는 기준’으로 통일하는 설계다. [출처: 원문 §3.2](https://arxiv.org/pdf/2609.22966v1#page=4).

## 3.2 명령 공간

```text
<arm> move <axis> <d>
<arm> rotate <rot> <theta>
<arm> point <pose>
<arm> gripper <g>
<arm> home
wait
done
```

| 명령·변수 | 의미와 제약 |
| --- | --- |
| `arm` | `left`, `right` |
| `move` | 세계 좌표계의 x/y/z축을 따라 GIP를 이동; 자세 유지 |
| `rotate` | 세계 좌표계의 roll/pitch/yaw에 해당하는 축으로 회전; GIP 위치 유지 |
| `point` | `down`, `forward`, `down45` 등 자주 쓰는 방향 preset |
| `gripper` | `open`, `close`, 또는 [0,1]의 정규화된 열림 값 |
| `home` | 팔을 초기 위치로 복귀 |
| `wait` | 환경이 안정화될 시간을 제공 |
| `done` | 과업 완료 확인을 요청 |
| 이동량·회전량 | 명령당 각각 최대 20cm, 90도로 제한 |

`move`와 `rotate`는 현재 상태에 대한 증분 명령이다. 또한 **축은 카메라 좌표계나 그리퍼의 로컬 좌표계가 아니라 세계 좌표계를 따른다.** 화면 오른쪽이 항상 세계 x축의 양의 방향이라는 식으로 해석하면 안 된다. 카메라와 좌표 규칙을 설명하는 환경 profile이 필요한 이유다.

‘discrete command’라는 표현도 구분해서 읽어야 한다. 명령 종류는 작은 어휘 집합이지만 거리·각도 같은 매개변수를 가진다. 논문에 없는 고정 1cm 격자나 모든 값의 정수 제한을 임의로 가정할 근거는 없다.

## 3.3 한 명령은 완결된 동작으로 실행된다

실행 계층은 의미 명령을 목표 GIP pose로 변환하고, 그 목표까지의 동작을 계획해 로봇이 정지 상태가 될 때까지 실행한다. 모델은 그 결과를 관측한 뒤 다음 판단을 수행한다.

이렇게 하면 VLM이 매 제어 주기의 joint velocity를 예측할 필요가 없다. 그 대신 중간 실행 과정에 대한 즉각적인 반응은 제한된다. 관측과 재계획이 명령 묶음 사이에 발생하는 구조이므로, 빠른 접촉 변화나 움직이는 물체를 추적하는 문제에서는 별도의 제어 대책이 필요하다. 이 부분은 시스템 구조로부터 얻는 리뷰어의 해석이다.

## 3.4 그리드와 다중 시점은 공간 추론을 돕는다

원문 구조도는 정면·손목·상단 관측을 예로 보여 주고, 실험에서는 grid-based localization의 효과를 평가한다. 그리드는 물체와 그리퍼의 위치 관계를 언어·숫자 판단에 연결하는 공간적 참조를 제공한다.

모델이 온라인에서 시뮬레이터의 정답 물체 pose를 직접 받지는 않는다. 그러나 **로봇 자신의 측정 상태, 카메라·작업 공간 규칙, 시각 주석은 제공받는다.** ‘특권 물체 pose를 쓰지 않는다’와 ‘RGB 이미지 외에는 정보가 전혀 없다’는 같은 말이 아니다.

# 4. 폐루프 수식과 메모리

원문 Eq. (1)은 다음 네 단계로 구성된다.

$$
(y_t,a_t)=\pi_\theta(L,E,D;I_t,x_t,F_{t-1},M_t)
$$

$$
(s_{t+1},F_t)=E_P(s_t,a_t)
$$

$$
(I_{t+1},x_{t+1})=O_P(s_{t+1})
$$

$$
M_{t+1}=U(M_t,a_t,y_t,F_t,x_{t+1})
$$

| 기호 | 의미 | 에피소드 동안 변화 여부 |
| --- | --- | --- |
| $\theta$ | 사전학습 VLM 파라미터 | 고정 |
| $L$ | 자연어 과업 지시 | 해당 과업의 조건 |
| $E$ | 로봇·환경 profile: 작업 공간, 카메라, 좌표·그리퍼 규칙 | 고정 |
| $D$ | 명령 primer와 과업 시연 | 고정 |
| $I_t$ | 주석이 있는 현재 시각 관측 | 변화 |
| $x_t$ | 측정된 현재 로봇 상태 | 변화 |
| $F_{t-1}$ | 앞선 실행으로부터 얻은 피드백 | 변화 |
| $M_t$ | 상호작용 기억 | 변화 |
| $y_t$ | 진행도 추정, 계획, 간결한 scratchpad | 모델 출력 |
| $a_t$ | 의미 명령 시퀀스 | 모델 출력 |
| $s_t$ | 물리 환경의 상태를 나타내는 형식적 변수 | VLM에 직접 노출되지 않음 |

첫 번째 식에서 모델은 현재 상황과 누적 정보를 보고 판단한다. 두 번째 식에서 실행 연산자 $E_P$가 명령을 물리 동작으로 옮기고 피드백을 만든다. 세 번째 식은 새 환경 상태를 다시 카메라·로봇 상태로 관측한다. 마지막 식은 모델의 해석과 실제 실행 결과를 함께 이용해 기억을 갱신한다. [출처: 원문 §3.1, Eq. (1)](https://arxiv.org/pdf/2609.22966v1#page=4).

## 4.1 무엇이 ‘학습’되는가?

가중치가 업데이트되지 않아도 행동은 바뀔 수 있다. ‘이전에 그리퍼를 닫았지만 물체를 잡지 못했다’, ‘명령한 이동량보다 실제 이동량이 작았다’, ‘지금은 왼팔이 물체를 들고 있다’ 같은 정보가 다음 프롬프트의 조건을 바꾸기 때문이다.

이는 optimizer를 통한 학습과 다르다. **이 논문의 적응은 에피소드 안의 문맥과 피드백을 이용한 적응**이다. 에피소드 내 기억 갱신을 로봇 전체의 영구적인 online fine-tuning으로 해석해서는 안 된다.

## 4.2 기억에는 어떤 정보가 들어가는가?

Figure 2는 과거 명령과 실행 결과를 담는 task history, 장면 이해·진행 판단·다음 계획을 담는 scratchpad, 어느 팔이 무엇을 들고 있는지와 파지 높이·그리퍼 상태를 담는 grasp facts를 보여 준다.

그리퍼가 화면에서 가려지거나 물체가 팔 뒤에 숨어도 과거 상태가 다음 판단에 도움을 줄 수 있다. 다만 모델이 기억에 쓴 문장 자체가 물리적 사실을 보장하지는 않는다. **추론한 사실과 센서·실행 결과로 확인한 사실을 구분하는 문제**는 신뢰성 측면에서 남는다. 원문은 기억을 포함한 전체 구조를 제시하지만, 기억만 제거한 별도의 수치 실험은 Table 3에 없다.

# 5. In-Context Learning: one-shot은 정확히 무엇인가?

## 5.1 두 종류의 예시를 함께 제공한다

원문 Eq. (3)은 시연 문맥을 다음처럼 나눈다.

$$
D=D_{\mathrm{prim}}\oplus D_{\mathrm{task}}
$$

$D_{\mathrm{prim}}$은 공통 **명령 primer**다. 기본 명령을 실행했을 때 어떤 효과가 나는지 보여 준다. $D_{\mathrm{task}}$는 **과업 수준의 시연**이다. 물체를 집고, 이동하고, 회전하고, 내려놓는 행동을 어떤 순서로 조합하는지 보여 준다.

따라서 논문의 zero-shot은 **과업 시연이 0개**라는 의미다. 명령 primer와 환경 규칙까지 제거한 완전 무지 상태가 아니다. one-shot은 **해당 과업의 시연 1개를 문맥에 제공**한다는 의미다. 모든 50개 과업을 단 하나의 공통 시연으로 해결했다는 주장은 아니다.

이 구분이 논문의 데이터 효율성을 이해하는 데 가장 중요하다. 과업별 optimizer update는 없지만, 인터페이스 사용법과 과업 전략을 전달하는 정보는 존재한다. [출처: 원문 §3.3, Eq. (3)–(5)](https://arxiv.org/pdf/2609.22966v1#page=6).

## 5.2 원래의 시연 궤적을 그대로 넣지 않는다

전문가의 raw trajectory는 연속적인 말단 동작과 그리퍼 상태를 포함한다. 그러나 온라인 모델이 사용할 수 있는 것은 의미 명령이다. 시연이 다른 행동 표현을 쓰면 모델은 예시를 실제 명령으로 다시 번역해야 한다.

RoboDawn은 이를 미리 변환한다.

1. 전문가 궤적을 말단 waypoint와 그리퍼 상태로 축약한다.
2. 각 waypoint를 이동·회전·그리퍼 명령의 짧은 시퀀스로 표현한다.
3. 명령 전후의 관측과 상태 변화, 실행 효과를 기록한다.
4. VLM이 기록을 검토한 뒤 각 라운드의 짧은 rationale을 작성한다.

이렇게 하면 예시는 모델이 온라인에서 실제로 출력할 수 있는 언어와 일치한다. **시연의 행동 표현과 온라인 행동 표현을 맞춘다**는 점이 단순한 이미지 예시 제공과 다르다.

## 5.3 시연 한 개 안에 여러 판단 단계가 있다

각 라운드의 예시는 $(I_j,x_j,r_j,a_j,f_j)$로 구성된다. 이미지, 로봇 상태, 짧은 이유, 명령, 명령의 물리적 효과를 포함한다. $f_j$는 연속된 상태 사이의 GIP pose와 그리퍼 열림 변화로부터 구한다.

즉 ‘한 번 보여 준다’는 것은 한 장의 사진이나 한 줄의 행동만 제공한다는 의미가 아니다. **하나의 성공 episode에 포함된 다단계 행동·관측·설명 묶음**이다. rationale 또한 사람이 당시 생각한 내용의 기록이 아니라, VLM이 시연을 보고 사후 작성한 설명이다.

## 5.4 시연이 회전 이해에 도움이 되는 이유

`move x 10`은 비교적 직관적이지만 `rotate yaw -30`의 실제 효과는 현재 자세, 좌표계, GIP 기준에 따라 이해해야 한다. 명령 이름을 읽는 것만으로는 공간적 효과를 충분히 이해하지 못할 수 있다.

저자들은 시연이 이런 명령의 의미와 과업 전략을 함께 grounding한다고 설명한다. 다만 회전 표현이 사전학습 데이터에서 덜 등장했기 때문에 어려워진다는 설명은 **저자의 가설**이며, 사전학습 데이터 빈도를 분석해 입증한 결과는 아니다.

## 5.5 긴 시연의 이미지 예산

RoboDojo의 장기 과업은 라운드 수가 많다. 원문은 라운드당 문맥 내 이미지 예산을 최대 16개 관측으로 제한하고, 예산을 초과하면 파지·회전·완료 같은 의미 있는 시점의 이미지를 남기는 전략을 설명한다. 시각적으로 반복되는 전환 단계의 이미지는 생략할 수 있지만, 전체 텍스트 궤적은 계획 안내를 위해 유지한다.

이는 모든 프레임을 그대로 모델에 넣는 방식이 아니다. **어떤 관측을 남길 것인지도 시스템 설계의 일부**이며, 시연 개수뿐 아니라 표현과 길이가 성능에 영향을 줄 수 있다.

## 5.6 데이터 누출을 피하는 방식과 남는 경계

시연 장면과 평가 장면은 분리한다. 시뮬레이션에서는 비교 정책의 학습에 사용되는 benchmark 전문가 궤적에서 시연을 가져오고, 실로봇 시연 수집 방식은 원격 조작을 설명한다. RoboTwin one-shot은 clean 장면의 시연을 제공하고 randomized 장면에서 평가한다.

이는 평가 장면의 정답 궤적을 그대로 보여 주는 것과 다르다. 하지만 같은 과업의 성공 전략을 제공하는 one-shot 설정이므로, 완전히 새로운 과업을 아무 시연 없이 해결하는 open-task 일반화와도 구분해야 한다. 특히 Table 5의 실로봇 결과는 과업 시연 없는 zero-shot이다.

# 7. RoboTwin 2.0 C2R: 실험 조건과 Table 1 해설

## 7.1 C2R은 무엇을 평가하는가?

Clean-to-Randomized 설정은 정돈된 환경의 시연으로 학습·적응한 방법이 domain-randomized 환경에서도 동작하는지를 평가한다. 양팔 조작 과업은 50개이고, RoboDawn은 과업마다 10회 독립 평가를 수행한다. 총 500회 규모다.

Full Set 비교 정책은 과업당 clean 시연 50개, 총 2,500개 시연으로 모든 과업을 공동 후학습하는 공식 프로토콜을 따른다. RoboDawn은 이 데이터로 가중치를 학습하지 않고, zero-shot 또는 clean set의 과업 시연을 문맥에 넣는 방식으로 평가한다.

## 7.3 무엇을 알 수 있는가?

GPT-6 Astra의 zero-shot 53.2%는 strong robot-trained baseline 여러 개를 넘지만, HarnessVLA 58.4%보다 높지는 않다. **zero-shot이 모든 비교 방법을 능가했다는 표현은 부정확하다.** one-shot 73.6%에서 Table 1의 가장 높은 결과를 보인다.

같은 backbone에서 시연 한 개의 효과는 GPT-6 Astra **+20.4%p**, Gemini **+15.2%p**다. 상대 증가율로 바꾸면 각각 약 38.3%, 32.3%이지만, 실험 비교에서는 혼동을 줄이기 위해 퍼센트포인트로 읽는 편이 명확하다.

이 결과는 시연을 gradient update 없이 사용하는 방식이 강력할 수 있음을 보여 준다. 그러나 2,500개 로봇 시연과 one-shot의 비교만으로 전체 시스템이 적은 정보로 학습했다고 결론 내릴 수는 없다. VLM의 대규모 사전학습 비용, primer, 환경 profile, 추론 계산은 별도로 존재한다.

# 9. RoboDojo: 장기 과업·기억·정밀성까지 확장하기

## 9.1 평가 범위와 지표

RoboDojo 시뮬레이션 suite는 양팔 플랫폼의 42개 과업으로 구성되고, 일반화·기억·긴 시간 범위·정밀 조작·open capability를 평가한다. 결과는 5회 실행의 평균으로 보고한다.

**Success rate**는 과업을 끝까지 완수했는지 측정한다. **Score**는 부분적인 진행도도 포착한다. 두 지표를 함께 보면 ‘대체로 올바르게 진행했지만 마지막 단계에 실패한 시스템’과 ‘처음부터 과업을 잘못 수행한 시스템’을 구분하는 데 도움이 된다. 다만 리뷰에서 score를 성공 확률이나 퍼센트 성공률로 재해석하지 않는다.

## 9.3 34-task 결과가 따로 있는 이유

42개 중 8개 open task는 다른 방법에 대응하는 학습 데이터가 없을 수 있다. 저자들은 이 과업을 제외한 34개에서도 RoboDawn을 평가한다. 이때 one-shot 성공률은 43.33%, zero-shot은 33.96%다.

이는 RoboDawn의 높은 결과가 open task를 포함한 평가에서만 나타나는 것은 아니라는 보조 근거다. 그러나 **34-task RoboDawn 수치와 42-task baseline 수치를 그대로 비교해 동일 조건의 우월성을 주장하면 안 된다.** 정확한 비교에는 baseline도 같은 subset으로 재평가한 결과가 필요하다.

| 과업 시연 설정 | 60 commands | 240 commands | 차이 (%p) |
| --- | ---: | ---: | ---: |
| 0-shot | 23.7% | 35.7% | +12.0 |
| 1-shot | 31.2% | 47.2% | +16.0 |

출처: [원문 Figure 3 및 §4.1.2](https://arxiv.org/pdf/2609.22966v1#page=8).Figure 3의 반올림 수치이며, Table 4의 35.67%, 47.17%와 표기 정밀도가 다르다.

원문은 기억과 실패 복구를 원인으로 설명한다. 추가 명령을 사용할 수 있으면 파지 실패 이후 다시 접근하거나, 잘못 놓은 물체를 재정렬하는 기회가 생긴다. 이를 통해 최초 계획이 완벽하지 않아도 성공할 수 있다.

여기서 늘어나는 것은 순수한 내부 추론 토큰만이 아니다. **환경과 상호작용하는 행동 기회도 증가**한다. command budget을 늘린 결과를 사고 토큰만 늘린 test-time compute 실험과 동일하게 취급하면 안 된다. 실제 배치에서는 추가 명령에 시간, API 비용, 물리적 실패 노출이 따르므로 성공률과 자원 소비를 함께 평가해야 한다. 이 비용 해석은 리뷰어의 관점이다.

# 11. 실행 효율: 높은 성공률의 반대편에 있는 비용

| 방법 | 추론 시간 | 출력 행동 수 | 동작 시간 | 추론/동작 비율 |
| --- | ---: | ---: | ---: | ---: |
| π0.5 | 101ms | 45.0 steps | 2.70s | 0.037 |
| StarVLA | 70ms | 16.0 steps | 0.96s | 0.073 |
| X-VLA | 143ms | 28.6 steps | 1.71s | 0.084 |
| FastWAM | 523ms | 27.3 steps | 1.64s | 0.32 |
| Motus | 1.93s | 16.0 steps | 0.96s | 2.01 |
| LingBot-VA | 8.89s | 22.2 steps | 1.33s | 6.67 |
| RoboDawn, Seed-2.1-Pro | 9.74s | 3.4 commands | 2.09s | 4.65 |

출처: [원문 Table 2, PDF 8쪽](https://arxiv.org/pdf/2609.22966v1#page=8).`LingBot-VA`는 Table 2의 표기를 그대로 따랐다. success table의 LingBot-VLA와 임의로 이름을 통일하지 않았다.

이 표는 RoboTwin 50개 과업에서 측정한 평균 비용을 비교한다. RoboDawn은 네트워크 지연 등 실용적 요인을 고려해 Seed-2.1-Pro로 측정했다. **73.6% 결과의 GPT-6 Astra가 9.74초에 실행된다는 결론은 낼 수 없다.** 최고 성능 모델과 지연 측정 모델이 다르다.

또한 `step`과 `command`는 동일 단위가 아니다. 의미 명령 하나는 여러 저수준 제어 step에 해당하는 완결된 동작을 만들 수 있다. ‘3.4가 45.0보다 작으니 더 효율적’이라는 비교는 타당하지 않다.

저자들은 추론/동작 비율이 0.5 미만이면 추론과 동작을 충분히 겹쳐 streaming inference를 할 가능성이 있다고 설명한다. RoboDawn의 4.65는 추론이 물리 움직임보다 긴 상황이다. 이 표만으로 이미 실시간 pipeline을 구현했거나 목표 주파수를 만족했다고 볼 수는 없다.

리뷰어 관점에서 이 시스템은 느린 조작과 계획·복구 연구에 매력적이지만, 빠르게 움직이는 대상 추적이나 높은 주파수의 접촉 제어에는 그대로 적용하기 어렵다. API 요청 수, 입력 이미지 토큰, 전체 과업 소요 시간, 성공당 비용을 함께 공개하면 실용성 비교가 더 명확해질 것이다.

## 13.1 의도는 맞지만 마지막 위치가 틀린다

동전을 집어서 작은 투입구에 넣는 과업은 대략적인 pick-and-place만으로 성공하지 않는다. 좁은 목표 영역에 정확히 정렬하고 접촉 근처에서 미세하게 조정해야 한다. 의미 명령 기반 이동은 높은 수준의 의도를 표현하기에는 좋지만, 마지막 정밀 조작에는 충분하지 않을 수 있다.

이 실패는 언어 추론을 더 길게 하는 것만으로 해결된다고 보장하기 어렵다. 더 정밀한 위치 추정, 작은 증분 조작, visual servoing 또는 접촉 기반 제어를 실행 계층에 넣는 방안을 생각할 수 있다. 이는 후속 설계 제안이며 원문에서 구현·검증한 개선은 아니다.

## 13.2 목표는 그럴듯하지만 경로가 충돌한다

IK 관련 실패에서는 예측한 의미 명령은 타당해 보여도 실제 움직임이 주변 물체와 충돌해 장면을 흐트러뜨린다. 말단의 최종 pose만 맞는다고 팔 전체의 이동 경로가 안전한 것은 아니다.

따라서 언어 수준 계획 평가와 물리 실행 검증은 분리해야 한다. 충돌 확인, 경로 재계획, 실행 전 거부 조건 등은 action interface의 신뢰성을 만드는 중요한 부분이 될 수 있다. 이 역시 리뷰어의 개선 제안이다.

## 13.3 모델의 ‘완료’와 benchmark의 ‘완료’가 다르다

액체 따르기에서는 컵으로 일부 액체를 옮겼지만 충분한 양을 붓기 전에 멈춘다. 모델은 작업이 끝났다고 판단하지만 benchmark의 성공 기준은 만족하지 못한다.

이 사례는 계획과 동작이 적절해도 완료 판단이 잘못되면 과업은 실패한다는 점을 보여 준다. `done`은 완료 확인 요청이지, 텍스트로 완료를 선언하면 물리 성공이 되는 명령이 아니다. 실제 시스템에서는 용량·높이·정렬 조건과 같은 검증 가능한 종료 기준을 명시하는 접근이 유용할 수 있다.

출처: [원문 §4.3, Figure 4](https://arxiv.org/pdf/2609.22966v1#page=9).세 범주는 대표 사례이며 전체 실패의 정량적 원인 분포를 제시한 것은 아니다.

# 14. 이 논문의 기여를 어떻게 평가할까?

## 14.1 행동 인터페이스 자체가 일반화의 중요한 변수다

같은 시각·언어 능력도 행동 표현이 joint-level vector인지, 이해 가능한 증분 명령인지에 따라 활용하기 쉬운 정도가 달라진다. GIP·세계 좌표계·실행 피드백을 정렬해 모델이 계획과 결과를 같은 언어로 비교할 수 있게 한 점이 설계의 핵심이다.

## 14.2 시연은 행동 정답뿐 아니라 사용 설명서다

시연의 역할은 ‘이 물체를 어느 위치로 가져가라’는 궤적 복제만이 아니다. 명령이 어떤 변화를 만드는지와 그 명령을 왜 그 시점에 써야 하는지를 함께 전달한다. 그 결과 과업 시연 한 개로도 큰 성능 증가가 관찰된다.

## 14.3 학습을 추론 시점의 상호작용으로 일부 이동한다

로봇 후학습 비용을 줄이는 대신 강한 VLM의 반복 추론, 문맥 관리, 관측·실행 루프에 의존한다. 따라서 이 논문은 ‘학습 비용이 사라진다’보다는 **적응을 어디에서 수행할지를 바꾼다**는 관점에서 읽는 편이 좋다.

## 14.4 VLA를 완전히 대체하는 결론은 아니다

저자들 역시 고주파 제어와 저수준 dexterity를 위한 로봇 데이터·정책 학습이 중요하다고 설명한다. RoboDawn의 강점은 넓은 과업에서 기존 추론 능력을 활용하는 데 있고, 약점은 정밀·빠른 물리 상호작용에 있다. 이 결과는 추론 중심의 상위 계층과 학습된 저수준 정책을 조합하는 후속 연구에도 동기를 제공한다.

## 15.1 ‘No robot training’의 범위를 정확히 쓰기

가장 방어 가능한 문장은 **‘이 시스템의 과업 적응을 위해 VLM 파라미터를 로봇 데이터로 업데이트하지 않는다’**다. VLM은 이미 대규모 사전학습을 거쳤고, 로봇은 실행 가능한 motion planning과 control 기반을 가진다. 이 기반까지 아무 학습·설계 없이 생겼다는 뜻은 아니다.

## 15.2 비교 예산과 정보량이 완전히 같지는 않다

Full Set robot policy와 API 기반 agent는 서로 다른 계산·데이터 사용 구조를 가진다. success rate 비교는 해당 benchmark에서의 결과를 보여 주지만, 같은 FLOPs·추론 시간·가격으로 더 우수한 방법이 무엇인지는 직접 답하지 않는다.

## 15.3 통계적 불확실성

원문 표는 평균 성공률 중심이며 모든 비교의 유의성이나 seed 간 분산을 충분히 제시하지 않는다. 특히 실로봇 과업별 10회는 한 번의 성공·실패가 10%p를 바꾸는 표본이다. ‘90% 성공’이라는 숫자만으로 안정적인 생산 환경 성능을 판단하면 과해석이다.

공식 코드 저장소는 추가적인 집계 정보를 공개하므로 재현 검토에 도움이 된다. 그러나 개별 조건, 과업 난이도와 seed에 대한 분석 없이 평균 순위를 일반적인 성능 순위로 확장하는 것은 피해야 한다.

## 15.4 회전과 cloth folding의 설명은 가설이다

사전학습에서 회전 표현을 덜 접했기 때문에 어렵다는 주장은 직관적이다. 하지만 지각 오류, 명령 표현, 경로 생성, 물체의 변형 등 다른 원인도 존재한다. 저자의 가설과 실제로 검증된 메커니즘을 분리해 읽어야 한다.

## 15.5 상용 backbone 재현성

같은 모델 이름을 사용해도 endpoint 버전, reasoning 설정, 이미지 처리, rate limit, 네트워크 조건이 결과에 영향을 줄 수 있다. 따라서 알고리즘과 benchmark seed를 공개하는 것만으로 장기간 동일 결과를 보장하기는 어렵다. 이 문제는 API 모델을 사용하는 embodied agent 전반에 해당하는 리뷰어의 재현성 지적이다.

# 16. 구현·재현을 위해 확인할 자료

공식 [RoboDawn 저장소](https://github.com/Hugo-AGI/RoboDawn)는 harness, demos, evaluation 및 benchmark submodule을 제공한다. [결과 브라우저](https://robodawn.top/results)는 모델의 관측, 계획, 명령과 실행 피드백을 에피소드 단위로 검토하는 데 유용하다. 원문 수치만 보는 것보다 실패가 어디서 시작하는지 확인하기 쉽다.

아래는 재현을 시작할 때 확인할 항목이다. 이 리뷰에서는 로봇 환경을 설치하거나 benchmark를 재실행하지 않았다.

1. **Benchmark 버전:** RoboTwin·RoboDojo submodule commit, 과업 구성과 evaluation seeds를 맞춘다.
2. **좌표·GIP 정의:** 손목 pose에서 GIP pose로의 변환, world frame 축, 회전 부호와 단위를 확인한다.
3. **프롬프트:** environment profile, command primer, reasoning 형식, memory 구성과 업데이트를 확인한다.
4. **시연 선택:** one-shot trajectory가 무엇인지, 평가 장면과 분리됐는지, waypoint 변환과 이미지 생략 규칙을 확인한다.
5. **실행 조건:** 라운드·명령 예산, timeout, parsing failure, IK 실패와 `done` 처리 규칙을 고정한다.
6. **모델 호출:** 정확한 endpoint, reasoning 설정, 이미지 입력, API 재시도 정책을 기록한다.
7. **결과 집계:** 성공률·부분 점수뿐 아니라 전체 시간, 호출 수, 비용, 실패 유형도 함께 비교한다.

## 구조를 이해하기 위한 의사코드

```python
# 원문 구조를 설명하기 위한 의사코드. 공식 코드의 API가 아니다.
context = environment_profile + command_primer + task_demonstrations
memory = initialize_memory()

while not episode_finished:
    images, robot_state = observe_robot()
    plan, commands = frozen_vlm(
        task, context, images, robot_state, feedback, memory
    )
    feedback = plan_and_execute_semantic_commands(commands)
    next_images, next_state = observe_robot()
    memory = update_memory(memory, plan, commands, feedback, next_state)
    episode_finished = check_completion_or_budget()
```

이 구조에는 gradient update가 없다. 그러나 `observe_robot`, `plan_and_execute_semantic_commands`, `check_completion_or_budget`의 품질이 전체 결과를 좌우한다. 모델 호출 한 줄만 복제해서 RoboDawn을 재현할 수 있는 것은 아니다.

# 17. 내가 이해한 핵심과 후속 연구 아이디어

내가 이해한 핵심은 **기존 VLM의 지능과 실제 로봇 사이에서 정보와 행동의 표현을 정렬하면, 새로운 action predictor를 학습하지 않고도 유용한 조작 능력을 끌어낼 수 있다는 것**이다. 이때 ‘정렬’은 명령 이름을 예쁘게 만드는 일이 아니라, 보는 지점·보고하는 상태·움직이는 기준·시연의 행동·실행 피드백을 일관되게 만드는 일이다.

이 논문을 바탕으로 다음 실험을 생각할 수 있다. 모두 리뷰어의 제안이며 원문에서 이미 달성한 결과는 아니다.

- **정밀 제어 계층 결합:** 큰 이동은 semantic command, 접촉 근처의 정렬은 visual servoing이나 low-level policy에 맡긴다. 마지막 단계 실패를 줄이는지 확인한다.
- **완료 검증 분리:** VLM의 진행 판단과 센서·규칙 기반 완료 확인을 분리한다. 액체 양이나 placement threshold 관련 오판이 줄어드는지 측정한다.
- **시연 구성 통제:** 이미지·rationale·실행 효과를 각각 제거해 시연의 어떤 부분이 성능을 만드는지 측정한다.
- **동일 예산 비교:** 같은 wall-clock time 또는 비용에서 VLA, agent, hybrid 방법의 성공률을 비교한다.
- **실패별 재시도 분석:** command budget 증가가 파지·정밀 조작·완료 판단 중 어떤 실패를 복구하는지 분류한다.
- **모델 선택:** 간단한 라운드는 저렴한 모델, 불확실한 회전·실패 복구는 강한 모델에 맡기는 방식으로 품질·지연 trade-off를 측정한다.
